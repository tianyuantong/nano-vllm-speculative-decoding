**随机与 greedy 两条实验线：相对普通 decode 的实际 token/s 提高至少 15%**

日期：2026-09-14。版本 `nano-15pct-v1`。状态：设计完成，未实施引擎补丁、未提交 GPU 作业。用户明确选择实际 token/s 为本轮主指标，并追加 greedy 版本。旧实验的时间主指标和结果不追溯修改。

**先回答“draft 和采样是否都过重”：采样层的执行组织有明确改进对象；draft 的总成本大，但其中包含算法必需的串行生成和真实补 KV，目前不能把它全部归为设计冗余。** 当前困难例中，target 少做计算省下约 2.201 秒，draft 执行和补算抵消约 2.057 秒，模型收益余量很薄；概率／抽样又多约 1.629 秒。这是阶段定位，不是纯 CPU 成本或可删除时间。后续方案分别检验执行组织和不需要概率验收的 greedy 路径，不承诺每条请求都能赢。

**15% 如何计算和认定。**

`Q = 实际最终提交的输出 token 数 / 完整 generate 时间`

`R = Q_投机 / Q_同期普通decode`，本轮目标 **R ≥ 1.15**。

时间包含请求 KV 初始化、prefill、draft、VERIFY、概率／采样、补算、必要传输、提交、同步和返回。排除模型加载、规定预热、采集、诊断以及调用前 RNG 创建／复位。不能把图外 RNG、输入 copy、输出 clone 放到计时外。输出数含已提交 EOS，不含未提交的草稿／bonus。

同一组／随机 seed 的计时重复先分别平均输出数 N 和时间 T，再对面板汇总 `Q=Σmean(N)/Σmean(T)`；不平均分组吞吐或倍数。完整时间比 `L=T_B/T_S`、N、每组／每 seed 的结果同时报告。若 R 达标但 L≤1，表述为“吞吐达标，完整生成时间未改善”；不另改主指标。

两条线各有自己的普通基线：

| 实验线 | 普通基线 | 投机候选 | 固定配置 | 可以说明什么 |
|---|---|---|---|---|
| 随机 | `B_random`：同控制器、无 draft、k0、T1 | `S_random`：0.6B draft，GPU token 续接，post-p/q Graph | target/draft T1、k3、三项采样删减 | 保持现有随机轨迹的执行优化能否使实际吞吐≥1.15 |
| greedy | `B_greedy`：同控制器、无 draft、k0、argmax | `S_greedy`：0.6B greedy draft、最长一致前缀验证 | target/draft T0、k4 | 不使用随机接受／残差的标准 greedy 投机能否达到≥1.15 |

禁止 `S_greedy/B_random` 作分母，禁止把 T0 与 T1 的成本差称为删除概率层的纯执行收益。k3 与 k4 是预先选定的两种模式配置，不比较其高低来断言最优 k。本轮不扫描 k。

这里的普通基线是当前离线控制器的无 draft 路径，双方同为 B4 排空、相同资源与适用的采样优化，不把历史慢 B 当新分母。它检验本项目投机功能的增益，不能外推为超过原版 nano 的 continuous batching 或生产服务吞吐；旧 vLLM 对照也采用 B4 排空。本轮不以重写 scheduler 改变所测问题。

此前生产 vLLM 的 14.6311% 是**greedy、k4、B4 排空、48 条已见输入**的观测吞吐提升；实际输出也不同。其普通/0.6B 草稿三次合计为 45324/43213 token、221.379231/184.128309 秒，完整时间比约 1.20231。软件环境为 vLLM `372477d2d`、Torch 2.13，当前 nano 为 Torch 2.9.1；因此是工程参照，不是当前随机线的可达证明，也不是同环境框架胜负对照。详见 [历史结果](</Users/tianyuantong/Documents/New project/outputs/vllm-four-methods-v1/REPORT.zh-CN.md>) 和本目录 `metrics-review.md`。

**用既有数据估算我们离目标多远。**

只为设计预算，假设旧／新 S1 输出不变且 B 时间不变，不把这些历史时间当未来分母：

| 负载 | 旧 S1 秒 | 吞吐×1.15所允许的 S1 秒 | S1 至少再省 | 相对旧 S1 |
|---|---:|---:|---:|---:|
| A1，24 条×3 seed 汇总 | 115.701975 | 97.092507 | 18.609468 秒 | 16.08% |
| A2，24 条×3 seed 汇总 | 85.816327 | 71.098577 | 14.717750 秒 | 17.15% |
| G4/110017 压力例，双方2048 token | 8.126732 | 5.703065 | 2.423667 秒 | 29.82% |

若 `r=N_S/N_B`，公共改动还让 B 省了 ΔB，所需门槛为：

`ΔS − (r/1.15)×ΔB ≥ T_S,旧 − (r/1.15)×T_B,旧`

G4 的整个 VERIFY 概率／抽样及返回阶段只有约 1.546785 秒，本次随机 Graph 还仅覆盖其子集。这个阶段算术足以说明不能承诺它独自令 G4 达到 15%，但它不是严格反事实下界，不能据此取消整个面板试验。压力例不承担“必须每组达15%”的门槛。

**随机线：只改 p/q 得到之后的一个完整块。**

保留当前 `_probabilities`、saved q、三角色随机数和原 arithmetic。依次完成：接受判断 → 首拒绝位置 → p/q 选行 → 残差及两份抽样评分 → tail 选择 → 累计 invalid。一次 replay 处理一个 k3 请求，全部请求串行复用同一份图，不按 request ID 建图。

| 固定输入 | 形状／类型 |
|---|---|
| target p values／mass／invalid | `[4,V]` FP32、`[4]` FP64、`[4]` bool |
| draft q values／mass／invalid | `[3,V]` FP32、`[3]` FP64、`[3]` bool |
| 候选 IDs／accept uniform | `[3]` int64、`[3]` FP64 |
| correction noise | `[1,V]` **FP64**，原 correction Generator |
| bonus noise | `[1,V]` **FP32**，原 bonus Generator |
| 之前累计的错误标志 | `[1]` bool，只参与最终累计，不顺便改变中间概率 |
| 输出 | count、tail、invalid 的独立小张量，随后仍整批校验／返回／提交 |

正式 V=151936。k0/1/2、N 和不支持布局保持原概率路径。即使模型由于混长走 eager，同批 k3 请求仍能用此概率图；不需要给模型添加 Graph 形状。

accept uniform、correction noise、bonus noise **图外生成、计时内执行**，保持原角色、dtype、shape、stride、调用次数和状态推进。两份 draw 都保留，即使最终只用一个；不把不同 RNG 轨迹带来的长度变化混成执行收益。

必须建立三个对照：`冻结旧实现 oldE → 仅提取确定性块的新 eager newE → 捕获同一块的 Graph`。先检验 oldE/newE，再检验 newE/Graph；不能只让两个新实现互证而共享提取错误。自然性能仍对同期冻结 oldE S1 比较。

一次完整 VERIFY 包装包括 p 构造、q cat、IDs 传输、三组 RNG、静态输入 copy、replay、小输出 clone、invalid 字典和整批 checked return；只有这整段净成本用于进入下一阶段。裸 replay 时间仅用于解释。输入 p/q 不被改写；前一个请求的 count/tail/invalid 不得被后一次 replay 覆盖。

使用一份独立私有图池、单 owner stream。显式大输入约 5.80 MiB，B4 每轮约 23.18 MiB 大输入 copy；这不是整个图池大小或性能预测。预定新增 process reserved 预算 **256 MiB**，设备 free 下限 **1 GiB**；超限停止资源门禁，不临时提高预算。先完成旧模型 Graph 自然预热和冻结，再捕获概率图并重新核对总占用。捕获前后要证明未改变原模型图支持域或挤出资源导致路径变化。

只有局部确定性块被捕获，不同时合批、不新增 torch.compile／Triton、不降精度、不把 mass 写成 1、不合并 draft 补算。PyTorch 的图地址／生命周期规则见 [2.9 官方文档](https://docs.pytorch.org/docs/2.9/notes/cuda.html#cuda-graphs)。

手算例：候选 `[0,1,2]`，接受随机数使第一个通过、第二个拒绝，第三个即使独立通过也不计入前缀；count=1，只提交 `[0, correction]`。全接受时 count=3、提交三个候选及 bonus。整个 batch 的 invalid 检查仍在任何 commit 之前。详细概率向量和噪声例子见 `sampler-design-review.md`。

组件的5%只是一次低成本筛查阈值，不能代替用户15%。组件通过但自然筛查只有+8%或+12%，记录局部改善，**停止此候选的扩大确认**；不会跑完144次再决定是否换目标。

真实样本从 A1 第0组与 A2 第4组各一次原路径 cap512/seed110017自然生成提取；预定round index为0、32，每个位置仅在完整B4且四请求均为k3时保存同轮全部四请求，最多16个请求片段。缺失位置不补别的seed/轮次凑数；任一round0的B4 fixture缺失则组件阶段标未完成。采集先独立clone，再转CPU，整次采集不作性能成绩；输出／停止／RNG须与原同模式自然轨迹核对。保存原始target logits、temperature、原saved q各段及拼接结果、p/q values/mass/invalid、候选、噪声、每角色Generator在VERIFY前后的状态、请求ID/轮次、原count/tail和源码指纹。仅保存噪声不能替代恢复Generator状态。

边界用例覆盖 count0/1/2/3、p=q、不同支持、极小正残差、非法mass／ID／uniform／noise、prior invalid、EOS前后、remaining1、k0/1/2、跨页与全接受补算。GPU概率频率门禁复用既有12类／每类10万次及冻结阈值，接入新最终入口；其中没有经过k3图的旧用例不充当该图覆盖，需要在补丁审阅时明确k3位置敏感用例及其预登记类别/阈值。真实词表用精确轨迹与缓冲对照，不做十万次全文生成。CPU参考不替代CUDA验证。

组件计时使用原始真实词表 logits／q 作为驻留输入，所有原本应发生的构造和copy照算。按A1/G4的round0完整B4各构造两个fixture：同轮原四请求，以及取其首请求的B1组件视图（不称自然B1生成），共四个固定fixture流，保留请求ID和对应独立RNG状态。每流3次预热、5个配对测量块，每实现每块固定100次完整包装VERIFY；oldE/newE/Graph顺序轮转，RNG只在块开始于计时外恢复，块内连续推进。共同D2H边界与原batch粒度一致，不每请求额外同步。报告原始5块时间、跨度、allocated/reserved峰值和图调用次数。

固定汇总门槛为 `C_point=Σ_fixture mean_block(T_Graph)/Σ_fixture mean_block(T_oldE)≤0.95` 且 `C_repeat=Σ_fixture max_block(T_Graph)/Σ_fixture min_block(T_oldE)≤0.95`；四fixture每块同为100次包装调用，不挑有利fixture，另列每流结果。newE用于提取桥接与收益解释，不能换作更慢分母。

**greedy 线：复用状态机，绕开概率后端。**

增加一个明确的采样模式选择，沿用现有控制器、Request/Query、PrivateKVPool、ModelRunner、VERIFY模型图和GPU token续接；不另建一套调度器或KV池实现。随机默认值保持，模式只在构造时决定，不在循环里堆多个实验开关。

最小适配必须同时覆盖入口与循环：greedy 只允许 T=0、无需创建或校验RequestRNG；随机仍要求有限正温度及原RNG。整批参数在任何 KV 分配或 request used 修改之前校验；请求单次使用标记与 RNG 消耗状态分开。greedy的draft不创建／保存q，也不积累概率占位对象，proposal辅助payload显式可空。现有 `probabilities is None` 会触发一热点q，必须将构造条件收窄为确实是N分支，不能靠返回None来实现greedy。metadata新增sampling_mode，greedy的RNG字段记N/A。否则仅把temperature改为0，会触发现有校验或继续支付随机后端成本。

greedy backend 的行为：

1. 普通B和draft从logits逐行argmax，保持PyTorch首次最大值的并列规则；不算softmax、不生成随机数。
2. 对每请求的target `[k_i+1,V]` logits求各行argmax。与对应draft IDs逐位置比较，只保留**最长连续相等前缀**。
3. 若首个不一致在j，提交前j个draft token与target第j行argmax；若全相等，提交全部draft与最后一行bonus。
4. k_i=0就是普通target一步；EOS/cap、请求结束、拒绝后双KV截断、全接受缺一格draft KV的补算，仍由原控制器处理。
5. GPU上形成count/tail，整批一次返回后提交。去掉随机概率检查并不等于取消logits有效性和索引／KV安全检查；有限值错误要整批阻断，不因greedy没有概率就静默argmax NaN。

首版可把真实logits按现有顺序串成一个张量做批量argmax，再按每请求query长度切结果，比较前缀；不引入概率Graph，不搬动模型LM head边界。实际补丁需确认cat增加的复制成本，B也使用相同适用的普通argmax路径，不人为把B留在更慢实现。

手算：k4候选 `[7,8,9,10]`，target五行argmax `[7,8,6,10,4]`。前两枚一致，第三枚拒绝，只提交 `[7,8,6]`；第四枚即使一致也不能保留。如果target为 `[7,8,9,10,4]`，提交五枚，下一轮照常补算最后一枚draft的KV。

greedy 固定 **k4**，是为了与旧vLLM模式接近；不宣称k4最优。target/draft仍为8B/0.6B、BF16/TP1、T0、B4排空、cap512、EOS生效。随机k3结果不能替代greedy的草稿有效性、KV或性能检查。

独立审查曾建议k3以减少一个draft步；总方案选k4，理由是旧vLLM同模式参照和既有Q5模型图支持，且本轮需要在看新结果前固定选择。子报告里的k3与12/36次建议是评审备选，执行以本方案及机器清单的k4、8/28/72次为准。计数／KV边界测试相应覆盖count0–4和target五行，不能照搬k3测试就记通过。

状态例：进入一轮历史长10、两模型已有9枚KV。k4草稿后draft有13枚KV，target VERIFY后有14枚；若接受前2枚再提交tail，历史长13，双KV截到12。若全接受再提交bonus，历史长15，target保留14枚KV而draft仅13枚，下一轮补最后一枚草稿的KV，再处理bonus。补算是状态依赖所需，不能只改计数或直接删除。

| G0 本地规则和补丁审阅 | argmax／最长前缀／bonus、T0入口、无RNG无q、复用KV及失败边界；模型桩和合成logits检查 | 原随机受影响回归不退步；同一提供的logits下规则与CPU参考一致；本人审阅最小增量 |
| G1 真实短验收 | A1第0/1组、cap128；B_greedy/S_greedy各2次，共8次 | 同模式重放，真实KV重建、0/部分/全接受、EOS/预算/并列/非法logits与回收；跨模式token/停止一致性单独记录 |
| G2 自然筛查 | A1全部6组，cap512；B_greedy/S_greedy各2次，共24次；另A2第4组各2次压力计时，共28次 | A1聚合R及最不利重复比≥1.15，且实现检查通过；压力例记录不删，不要求每组15% |
| G3 正式计时确认 | A1/A2各6组，B_greedy/S_greedy各3次，共72次 | 两面板聚合R及最不利重复比≥1.15；这是3次时间重复，不是3个随机seed |

greedy只记录seed0作为环境metadata，不消费采样RNG。新/旧随机输入与输出检查证明新增模式没有污染随机路径。G1的受控边界测试不能只等自然生成恰好覆盖；需要强制合成候选／logits与独立KV重建。

**两条线分别报告性能与正确性范围，不偷偷提高或降低15%的含义。**

实现规则、索引安全、有效KV、提交／回收、同模式重放是共同门禁。随机旧／新 S1 的token、停止、角色RNG必须相同，才能认定纯执行优化；B与投机随机文本不要求相同。

greedy B/S跨模式token不一致时，先在首次分歧的公共前缀上保存单步／VERIFY logits、argmax并独立重建有效KV。预定最多2个首分歧用例用于定位，不扫描输入直到找到一致样本。确认比较位置、KV或新backend实现错误则停止；尚未排除的新状态/索引异常不能继续冒称实现通过。若实现检查通过而跨形状有限精度关系仍OPEN，保留这一限制，不把差异默认归因浮点，也不新增margin、每步target重查或强制回退以掩盖。

用户选的是此前vLLM同口径的**观测吞吐**。所以跨模式输出不一致不会被隐含改写为“吞吐目标永远不能记录”。R≥1.15且实现门禁通过时可报告“greedy观测吞吐达到目标，X/48输出与停止一致，未证明逐token无损”；仅全部token与停止也一致时，才增加“所测同输出范围”的更强表述。两边实际输出相等时R=L；否则二者不同。两模式均未做任务质量基准，不宣称质量保持。

**正式确认如何避免再挑出一个好看的15%。**

- A1仍为原开发文件的组02/06/07/08/10/11，共24条；A2为应用文件组00–05，共24条。token IDs与请求ID已在 `inputs.proposed.json` 固定，48条互不重复，不重新tokenize、不重组batch。
- 两面板输入均已见，A2第4组还用于诊断。正式阶段称“预定输入上的新随机条件确认／greedy重复确认”，不称输入盲测。
- 随机筛查seed110017；确认seed **76607125、285090488、315425581**，由固定namespace的SHA256导出，生成方法与已查旧seed见 `seed-design.json`。执行前再与冻结任务台账核对，不能根据结果更换。
- 随机每(panel,group,seed,mode)一个worker，完整自然预热、冻结后测2次；greedy确认每(panel,group,mode)一个worker测3次。双方每对放在同一GPU分配内，group/seed奇偶交替先后；不跨GPU拼同一对照。
- 每个面板分别计算总体R。另计算保守重复比：`R_repeat = (ΣN_S / Σmax_repeat T_S) / (ΣN_B / Σmin_repeat T_B)`；N取同轨迹重复均值，各group/seed取最慢S与最快B时间。这是工程波动余量检查，不是置信区间。
- **该面板正式通过：R≥1.15 且 R_repeat≥1.15。** 随机另要求3个seed各自R>1，并公布每seed最低值；不声称每seed或每组都达15%。greedy的3次计时不充当随机覆盖。
- 一个面板通过、另一个没过，就按面板收窄结论，不将两者合并掩盖失败。随机通过不代替greedy通过，反之亦然。
- 正式确认只能执行一次已冻结候选；未通过不追加seed、不挑快重复、不在确认面板调k或补优化。没有实现错误的慢结果照常保留。

**停止一条候选，和放弃最终目标，是两件事。**

本轮每条线只有一个执行候选，允许修复与其直接相关的明确bug后重新检查，不允许性能没赢就不断扩大设计。随机Graph若包装后无收益，停止这份候选；有收益但不到15%，保留实测并停止其正式扩大确认。greedy若未达到15%，同样记录界限，不换k、输入或baseline。

执行优先级建议先完成greedy的G0–G2：它直接对齐此前vLLM的采样模式，也能较快检验不经过随机概率层时这对模型是否还有足够收益。随机R0–R3保持独立，greedy胜出不替代它；各自筛查通过才进入各自确认。此优先级不改变共享源码必须静止到作业结束的要求。

下一份设计必须由结果决定：如果Graph节省被图外概率／RNG／copy吃掉，才讨论扩大纯张量块或批处理；如果greedy也显示模型执行余量不足，才讨论draft调用／补算组织或改变proposal方案。当前材料不能预先保证其中任一路径达标。任何新RNG契约、融合、模型形状、动态k、refill或模型对都属于新设计与相应审阅，不自动拼成这轮的一部分。15%目标保留，未达到就明确写未达到。
